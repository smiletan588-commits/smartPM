# SmartPM AI 效果评估指南

## 实验目标

使用 `ai-evaluation-dataset.json` 中 20 个不同类型的项目需求，并补充 `ai-planning-edge-cases.json` 中 5 个规划边界场景，对 AI 项目规划的可用性与系统稳定性进行可复现评估。每条需求至少运行一次，建议在相同模型、Prompt 版本与网络环境下重复 3 次。边界场景用于验证信息澄清、无需拆解、去重、非研发适配和日期冲突，不能替代真实用户评价。

## 操作步骤

1. 为每条数据创建独立项目，将 `requirement` 作为项目描述。
2. 在“明确需求”中提供目标、预期交付物和工作范围；仅有项目名称时，记录系统是否阻止生成。调用对应的 AI 规划入口，记录结构解析、耗时、任务数、待确认假设和服务端检查提示。系统会写入 `pm_ai_operation_log`。
3. 两名评价者独立按 1–5 分评价完整性、清晰度和可执行性，并分别记录重复任务、错误岗位建议、超出范围的任务、所需人工修改项和失败样例。
4. 审核草稿，记录每项修改、删除、合并和重新生成；根据真实决策决定是否确认创建，不应为提高采纳率而全部应用。确认后变更的任务数填入结果表。没有确认前，验证任务表没有变化。
5. 从数据大屏记录 AI 成功率、平均响应时间、采纳率、平均评分和 AI 生成任务占比。

## 指标定义

| 指标 | 计算方式 |
| --- | --- |
| 解析成功率 | 成功返回结构化计划次数 / 总调用次数 |
| 平均响应时间 | 所有调用的 `duration_ms` 算术平均值 |
| 采纳率 | 已应用 AI 结果次数 / 成功调用次数 |
| 评分 | 完整性、清晰度、可执行性各 1–5 分；系统内评分取总体感受 1–5 分 |
| AI 任务占比 | `ai_generated = 1` 的非回收站任务 / 全部非回收站任务 |
| 重复率 | 与项目已有任务或同次草稿重复的任务数 / 生成任务数 |
| 错误岗位建议率 | 与项目类型不符的岗位建议数 / 有岗位建议的任务数 |
| 平均人工修改量 | 为达到可应用状态，编辑、删除、合并及单项重新生成的次数 / 草稿数 |
| 可执行性 | 两名评价者独立对“动作、交付物、验收标准”打 1–5 分后取均值 |

将原始值填入 `ai-evaluation-results-template.csv`。论文中至少输出场景分组统计表、指标总览表、响应时间柱状图和评分雷达图，并报告失败样例，不要只展示最优结果。

改造前后的对比须使用相同场景、模型、温度参数和评分表；不能把服务端校验通过率等同于内容质量。若尚未完成 20+5 场景的双人盲评，应明确标注为“待评估”，不能据此宣称 AI 任务质量已经提升。
